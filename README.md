# Naver 매물 랭킹 모니터

네이버페이 부동산의 동일매물 노출 순서를 주기적으로 확인하고 화면 중앙에 통합 알림을 표시하는 .NET 8 WinForms 앱입니다.

## 주요 기능

- 단체 ID를 `realtorId`로 전달해 내 매물 목록 조회
- 소재지(`cortarAddress` 등), 매물명·등록 설명(`articleFeatureDesc` 등), 건물명·층 정보, 거래유형, 거래금액 표시
- 매물별 이전랭킹·현재랭킹 및 동일매물 수 표시
- 랭킹 상승은 현재랭킹에 빨간색 `↑변동폭`, 하락은 파란색 `↓변동폭` 표시
- `▶` 버튼으로 동일매물과 공인중개사/정보제공사 펼치기
- 모든 랭킹 변경, 설정한 순위 숫자 이상으로 하락, 타 중개사 가격 변경, 단독매물에 경쟁 매물 생성 내용을 조회당 한 개의 중앙 팝업으로 통합 알림
- 팝업에서 변동 건별로 `매물명(건물명/단지명) | 거래유형 거래금액 | 변동이력` 카드를 표시하고, 순위 상승·하락·가격 변경·동일매물 발생에 따라 변동이력을 굵은 글씨와 구분 색상으로 강조
- 한 조회에서 발생한 변동을 순위변동·순위기준·동일매물 가격변동·동일매물 추가 유형별 독립 팝업으로 분리하고, 여러 유형이 동시에 발생하면 팝업을 계단식 위치로 각각 표시
- 새 조회에서 같은 변동 유형의 팝업이 이미 열려 있으면 해당 팝업만 최신 내용으로 교체하고, 새 내용이 없는 다른 유형의 기존 팝업은 사용자가 직접 닫을 때까지 유지
- 메인 창이 시스템 트레이에 숨겨져 있어도 랭킹 조회 완료 팝업 표시
- 프로그램 중복 실행 차단 및 이미 실행 중일 때 안내 메시지 표시
- Google Apps Script·스프레드시트 기반 로그인, 회원가입 및 공지사항
- 멤버십 기간과 고유 PC 토큰 수를 이용한 로그인 제한
- 로그인 성공 시 토큰·로그인일시·아이디·공인 IP 이력 기록
- GitHub Releases 최신 버전 확인 및 태그 기반 자동 게시
- 창을 닫아도 시스템 트레이에서 자동 조회
- 건물과 상승 랭킹을 조합한 전용 실행 파일·창·시스템 트레이 아이콘
- 단체 ID 저장 선택(신규 환경에서는 기본 체크, 로컬 사용자 설정에만 저장)
- 매물목록 전체를 한 화면에 표시하고 목록 조회 직후 전체 랭킹 조회
- 사용자 매물 전체 목록을 먼저 표시한 뒤 건별 랭킹 조회하고, 하단에 `전체 N건 중 조회건수/리스트건수: X/N` 진행 상태 표시
- `매물목록조회`는 기존 목록이 있으면 기존 매물 순위 재조회와 최신 목록 수집을 병행하고, API 결과 기준으로 신규 매물을 추가하고 종료된 매물을 삭제한 뒤 신규 매물 순위까지 조회합니다. 옆의 `순위조회`는 현재 목록 전체를 재조회합니다.
- 목록 페이지는 빠른 전용 호출 간격으로 수집하고 반복 페이지를 감지해 중단하며, 수집 중 페이지·누적 건수 표시
- 랭킹 API의 기존 건별 3초 강제 대기를 제거하고 0.2초 호출 시작 간격·최대 5건 병렬 처리로 개선하며, 완료되는 결과부터 즉시 화면 반영
- 매물 목록 상단 `정렬방법` 라디오 버튼으로 랭킹 낮은순·높은순, 동일매물 많은순·적은순 정렬하며 기본값은 동일매물 많은순
- 검색조건의 `단일매물 제외`를 체크하면 순위 조회 결과 동일매물 수가 1 이하인 매물을 숨기며, 이후 순위 조회에서 2건 이상으로 증가하면 목록에 자동으로 다시 표시
- 건별 랭킹은 현재 정렬 화면에서 가장 위에 있는 미조회 매물부터 순차 조회
- 매물·순위 재조회 중 중앙 진행 모달이나 화면 잠금을 사용하지 않고 하단 상태표시줄에만 진행 상황 표시. 조회 중에도 목록 선택·스크롤·정렬과 창 닫기/열기 가능
- `광고분석` 버튼을 누르면 내 매물 정보를 단지정보(단지번호·단지명)로 group by 한 목록을 별도 API 조회 없이 팝업으로 즉시 표시
- `매물동기화`(시작 시 캐시 자동 동기화, 주기적 자동 조회 포함) 완료 후 랭킹 조회에 실패한 매물이 남아 있으면 다음 예정 조회 시각 전까지 실패 매물만 최대 5건 병렬로 반복 재조회하며, 회차마다 정상 조회된 매물은 즉시 목록에 반영하고 남은 실패 매물이 없어지면 자동으로 멈춘다
- HTTP 429 발생 시 최소 30분 자동 쿨다운 및 반복 팝업 방지

## 실행

Windows 10/11과 [.NET 8 Desktop Runtime](https://dotnet.microsoft.com/download/dotnet/8.0)이 필요합니다.

```powershell
dotnet run --project .\src\NaverPropertyRanking_Blog\NaverPropertyRanking_Blog.csproj
```

Google 인증을 활성화한 경우 앱 실행 직후 로그인 화면이 먼저 표시됩니다. 로그인 화면의 `회원가입` 탭에서 아이디·패스워드·이름만 입력해 가입할 수 있습니다.

아이디와 패스워드는 각각 최소 4자이며, 패스워드는 최대 100자까지 입력할 수 있습니다.

1. 로그인 후 상단에 네이버 부동산 단체 ID를 입력합니다.
2. 필요하면 `저장`을 체크합니다.
3. `appsettings.json`의 `RealtorArticleList`와 `Ranking`에 각각 해당 API의 Bearer 토큰과 Cookie를 설정합니다.
4. `매물목록조회`를 누르면 조회 및 알림 설정창이 열립니다.
5. 설정을 확인한 뒤 `확인`을 누르면 메인 창이 시스템 트레이로 숨고, 백그라운드에서 매물 전체 목록과 전체 랭킹을 조회합니다.
6. 조회가 끝나면 성공·실패·변동 건수를 포함한 통합 팝업이 화면 중앙에 표시됩니다. `확인`은 팝업만 닫고, `시스템 열기`는 메인 창을 복원합니다.
7. 표의 `▶`를 눌러 동일매물을 확인합니다. 행을 두 번 클릭하면 API에서 받은 `complexNo`와 매물번호를 사용한 네이버 단지 매물 페이지가 열립니다.

매물번호 입력, 표시 행수, `매물 조회 시 랭킹 바로조회`, `랭킹 새로고침` 컨트롤은 메인 화면에 표시하지 않습니다. 표시 행수는 항상 `전체`, 목록 조회 후 랭킹 조회는 항상 사용됩니다. 수동 재조회는 상단 `순위조회` 버튼 또는 시스템 트레이의 `지금 새로고침`을 이용하며, 매번 현재 목록 전체를 다시 조회합니다.

목록에는 매물 선택용 체크박스가 없습니다. 재조회 중에도 목록 확인·스크롤·정렬과 창 닫기/열기가 가능하며, 진행 상황은 중앙 모달 없이 하단 상태표시줄에만 표시됩니다.

창을 닫으면 시스템 트레이로 숨고 별도의 백그라운드 재조회 없이 대기하며, 이후 갱신은 설정된 주기의 자동 조회 또는 트레이의 `지금 새로고침`으로 이루어집니다.

## appsettings.json

실행 파일과 같은 폴더의 `appsettings.json`에서 서로 독립적인 API 프로필을 불러옵니다.

- `Api.BaseUrl`: 네이버 부동산 API 기준 주소
- `Api.RealtorArticleList`: 참고 프로젝트의 첫 번째 `중개사 매물목록` 탭에 해당하는 설정
  - `Endpoint`, `RealtorIdParameter`: 목록 엔드포인트와 단체 ID 쿼리 이름(현재 `realtorId`)
  - `Headers`: 중개사 매물목록 API 전용 Authorization, Referer, Cookie, User-Agent 등
  - `Params`: realEstateType, tradeType, order, page, zoom
- `Api.Ranking`: 매물번호별 동일매물 랭킹 조회 전용 설정
  - `Endpoint`, `Headers`, `Params.index`
- `GoogleAuthentication`: Google Apps Script 인증 API 설정
  - `Enabled`: 로그인 기능 활성화 여부
  - `WebAppUrl`: Apps Script 웹 앱의 `/exec` 주소
  - `PublicIpEndpoint`: 로그인 이력에 기록할 공인 IP 조회 주소
  - `RequestTimeoutSeconds`: 인증 요청 제한 시간
  - `HeartbeatIntervalSeconds`: 활성 접속 신호 주기. 기본 120초
- `Update`: GitHub Releases 버전 확인 설정
  - `Enabled`, `CheckOnStartup`: 업데이트 확인 활성화 여부
  - `CurrentVersion`: 현재 배포 버전
  - `ReleasesApiUrl`: `https://api.github.com/repos/OWNER/REPOSITORY/releases?per_page=100` 형식
  - `ReleaseTagPrefix`: 이 프로그램의 릴리스를 구분할 태그 접두사. 기본 예시는 `NaverPropertyRanking_Blog-v`
  - `ReleasesPageUrl`, `AssetName`: 릴리스 페이지와 직접 교체할 EXE 파일명

단체 ID는 `appsettings.json`에 두지 않습니다. 메인 화면에서 입력하며 `저장`은 신규 환경에서 기본 선택됩니다. 선택한 경우에만 로컬 사용자 설정에 보관됩니다. 로그인 ID·단체 ID가 일치하는 로컬 매물 캐시가 없으면 `매물목록조회`를 눌러 최초 목록을 받아야 합니다. 캐시가 있으면 앱 시작 시 캐시를 먼저 표시한 뒤 순위 재조회와 `realtorId={단체 ID}` 최신 목록 수집을 자동으로 시작합니다. 반환된 각 네이버 매물번호를 기준으로 별도의 랭킹 프로필을 사용해 순위를 조회합니다. 안전한 형식 예시는 `appsettings.example.json`을 참고하세요.

실제 `appsettings.json`에는 로그인 Cookie가 포함될 수 있으므로 `.gitignore`에서 제외했습니다. 파일을 공유하거나 저장소에 커밋하지 마세요.

Bearer 토큰이나 Cookie가 없으면 앱은 해당 프로필로 네이버에 요청을 보내지 않습니다. JWT의 `exp` 값만으로는 요청을 사전 차단하지 않으며, 인증 가능 여부는 네이버 서버의 실제 응답으로 판단합니다. `appsettings.json`에서 두 프로필의 인증값을 교체하면 잘못된 인증 요청으로 만들어진 로컬 429 대기는 한 번 초기화됩니다.

### 로그인 및 Google 스프레드시트 설정

Google 인증 서버 코드는 [google-apps-script](google-apps-script) 폴더에 있습니다. [설정 안내](google-apps-script/README.md)에 따라 스프레드시트와 Apps Script 웹 앱을 배포한 뒤 다음 값을 변경합니다.

```json
"GoogleAuthentication": {
  "Enabled": true,
  "WebAppUrl": "https://script.google.com/macros/s/배포ID/exec",
  "PublicIpEndpoint": "https://api.ipify.org",
  "RequestTimeoutSeconds": 20
}
```

`configure()`를 최초 한 번 실행하면 다음 탭이 자동 생성됩니다.

- `회원정보`: 아이디, 비밀번호해시, 솔트, 이름, 가입일시, 멤버십 시작일자, 멤버십 종료일자, 사용가능PC수
- `이력`: 토큰, 로그인일시, 아이디, 아이피
- `접속현황`: 세션ID, 토큰, 아이디, PC명, 로그인일시, 마지막신호일시, 종료일시, 상태
- `공지사항`: A1의 `공지내용` 헤더 아래 A2부터 한 행에 하나씩 등록
- `회원_단체`: `매물목록조회` 클릭 시 로그인 회원과 단체 ID를 조회하고, 없는 조합만 `id`, `단체id` 두 열에 등록

패스워드는 스프레드시트에 평문으로 저장하지 않습니다. PC 토큰은 Apps Script의 서버 비밀값과 Windows PC 식별값으로 생성됩니다. `접속현황`에서 heartbeat가 유효한 `ACTIVE` 상태의 고유 토큰 수가 `사용가능PC수`를 초과하면 로그인을 거부합니다. 앱은 기본 2분마다 접속 신호를 보내고, 정상 종료하면 즉시 `LOGOUT`, 강제 종료·정전·네트워크 단절이면 기본 5분 뒤 `EXPIRED` 상태로 처리됩니다. `이력` 탭은 감사 기록일 뿐 PC 제한 계산에는 사용하지 않습니다. 공인 IP는 `PublicIpEndpoint`에서 클라이언트가 확인한 값이므로 보안 감사용 절대 증거로 사용하면 안 됩니다.

회원정보의 멤버십 기간이나 사용가능PC수를 변경하면 다음 heartbeat에서 다시 검사합니다. 멤버십 종료 또는 PC 수 축소로 현재 세션이 허용 범위를 벗어나면 앱에 안내를 표시하고 종료합니다.

신규 회원의 멤버십 시작일과 종료일은 `yyyy-MM-dd` 형식으로 저장합니다. 시작일은 가입일, 종료일은 8일 뒤 날짜이며 로그인·heartbeat는 시각을 제외한 날짜만 비교합니다. 종료일 당일부터는 사용할 수 없습니다.

로그인 성공 시 `공지사항` 시트의 내용을 읽어 로컬 설정에 저장하고 메인 화면 제목 오른쪽에 한 줄씩 표시합니다. 공지는 1분마다 다음 행으로 자동 이동하며 마지막 행 다음에는 첫 행부터 다시 표시합니다. 공지 영역에서 마우스 휠 또는 세로 스크롤을 사용해 직접 이동할 수도 있습니다.

설정 화면에서 확인한 뒤에도 메인 창은 닫히거나 트레이로 숨지 않습니다. 매물 목록을 처음 불러올 때 중앙 진행 모달을 표시하지 않고, 매물 한 건과 해당 랭킹 조회가 완료될 때마다 그리드에 반영합니다. 이미 표시된 행은 조회가 계속되는 동안에도 선택·펼치기·링크 열기·복사가 가능합니다. 중복 조회 방지를 위해 `매물목록조회`와 설정 변경은 전체 조회가 끝난 뒤 다시 활성화됩니다.

매물 조회가 끝날 때마다 현재 목록과 랭킹 표시 정보는 로그인 ID·단체 ID 조합별 로컬 캐시에 저장됩니다. 캐시는 실행 파일과 같은 위치의 `listing-cache.inf` 파일에 Windows 사용자 범위로 암호화되어 저장됩니다. 다음 실행에서는 로그인 ID와 저장된 단체 ID가 모두 일치하는 캐시만 복호화해 즉시 표시한 뒤 `매물목록조회`와 같은 동기화 기능을 자동 실행합니다. 화면에 복원한 기존 매물의 순위를 조회하는 작업과 최신 매물목록 API 작업을 별도로 시작하고, 매물번호를 비교해 API 결과에만 있는 신규 매물은 추가·순위 조회하며 API 결과에 없는 기존 매물은 목록과 캐시에서 삭제합니다. 다른 회원이나 단체의 목록은 섞이지 않습니다. 별도의 1시간 주기 저장 작업은 실행하지 않습니다.

조회 중 창을 닫아 트레이로 숨긴 다음 다시 열어도 중앙 진행 모달은 다시 표시하지 않습니다. 진행 상태는 하단 상태 표시줄과 그리드의 갱신 결과로 확인합니다.

로그인 화면이 열리면 Apps Script와 공인 IP 조회를 미리 시작합니다. 기존 8,000회 해시로 저장된 회원은 새 스크립트 배포 후 첫 로그인에서만 이전 해시를 검증한 뒤 빠른 형식으로 자동 전환되므로, 두 번째 로그인부터 처리시간이 줄어듭니다.

로그인 기능을 배포하기 전에는 `Enabled`를 `false`로 유지하면 기존처럼 로그인 화면 없이 실행할 수 있습니다.

### GitHub 버전 관리 및 자동 게시

[release.yml](.github/workflows/release.yml)은 `NaverPropertyRanking_Blog-v0.0.2` 같은 태그가 푸시되면 다음 작업을 자동 실행합니다.

1. .NET 8 복원·빌드·스모크 테스트
2. Windows x64 단일 EXE 게시
3. 배포용 설정의 현재 버전을 태그 버전으로 변경
4. GitHub Release 생성
5. `NaverPropertyRanking_Blog.exe`를 압축하지 않고 Release 자산으로 직접 업로드

```powershell
git tag NaverPropertyRanking_Blog-v0.0.2
git push origin NaverPropertyRanking_Blog-v0.0.2
```

배포할 때 `appsettings.json > Update.CurrentVersion`과 Release 태그 버전을 동일하게 맞춥니다. 예를 들어 기존 버전이 `0.0.1`이면 새 EXE를 `0.0.2`로 빌드하고 `NaverPropertyRanking_Blog-v0.0.2` Release에 `NaverPropertyRanking_Blog.exe`라는 이름으로 올립니다.

앱은 시작 시 `ReleasesApiUrl`에서 `ReleaseTagPrefix`가 일치하는 최신 정식 Release를 선택하고 현재 버전보다 높은지 비교합니다. 사용자가 업데이트를 승인하면 EXE를 임시 폴더에 다운로드하고 PE 서명과 파일 버전이 Release 버전과 일치하는지 검사합니다. 검사가 끝나면 별도 PowerShell 업데이트 프로세스를 시작하고 현재 프로그램을 종료합니다. 업데이트 프로세스는 기존 EXE를 백업한 뒤 새 EXE로 교체하고, 외부 `appsettings.json`의 `CurrentVersion`을 새 버전으로 변경한 후 프로그램을 재실행합니다. 교체가 실패하면 백업 EXE를 복원하고 실행 파일 폴더의 `update-error.log`에 오류를 기록합니다. `appsettings.json`과 `listing-cache.inf` 등 사용자 데이터 파일은 덮어쓰지 않습니다.

## 알림 기준

- `모든 랭킹 변경`: 이전 조회와 순위가 다르면 알림
- `랭킹 기준`: 예를 들어 기준이 5이면 1~4위에서 5위 이상 숫자로 내려간 순간 알림
- `동일매물 가격 변경`: 내 매물을 제외한 동일매물의 표시 가격이 바뀌면 알림
- `단독매물 상태 변경`: 경쟁 동일매물 0건에서 1건 이상으로 바뀌면 알림

최초 조회는 비교 기준을 저장하므로 변경 항목은 만들지 않습니다. 다만 조회 완료를 알리는 중앙 팝업은 표시되며 `변동 내역이 없습니다.`라고 안내합니다. 이후 조회부터 변동 항목을 유형별로 묶어 한 개의 팝업에 표시합니다.

## 빌드와 점검

```powershell
dotnet build .\NaverPropertyRanking_Blog.sln -nologo
dotnet run --project .\tests\NaverPropertyRanking_Blog.SmokeTests\NaverPropertyRanking_Blog.SmokeTests.csproj
```

Visual Studio 게시 화면에서 `SingleFile-win-x64` 프로필을 선택하면 .NET Runtime을 포함한 Windows x64용 실행 파일이 `D:\Source\Release\NaverPropertyRanking_Blog`에 생성됩니다. 명령줄에서는 다음과 같이 게시할 수 있습니다.

```powershell
dotnet publish .\src\NaverPropertyRanking_Blog\NaverPropertyRanking_Blog.csproj -p:PublishProfile=SingleFile-win-x64
```

단일 파일 게시 프로필은 `NaverPropertyRanking_Blog.exe`와 외부 `appsettings.json`을 함께 생성합니다. 실행 파일 옆의 외부 설정이 EXE 내부 설정보다 우선하므로 인증값을 변경한 뒤 다시 게시할 필요 없이 앱만 재시작하면 됩니다. 외부 파일을 삭제하면 EXE 내부에 포함된 기본 설정을 사용합니다.

## 주의사항

이 앱은 네이버가 개발자용으로 공개·보증한 API가 아니라 현재 웹 화면이 사용하는 읽기 전용 엔드포인트에 의존합니다. 응답 형식이나 인증 방식이 예고 없이 바뀔 수 있습니다. 네이버 이용약관과 관련 법규를 확인하고 본인이 관리할 권한이 있는 매물만 낮은 빈도로 조회하세요.

앱은 401/403/429에서 자동 우회하거나 반복 재시도하지 않습니다. 429가 발생하면 서버의 `Retry-After` 또는 기본 30분 동안 모든 요청을 중지하며, 이 시각은 앱을 재시작해도 유지됩니다. 제한이 풀린 뒤에도 반복된다면 조회 주기를 늘리고 동시에 실행 중인 다른 크롤러를 중지하세요. 기본 조회 간격은 10분이며 최소값은 2분입니다.

각 네이버 요청은 최소 3초 간격으로 순차 실행됩니다. 이미 429가 표시된 상태에서는 앱을 반복 실행하거나 새로고침하지 말고 상태 표시줄에 안내된 시각까지 기다려야 합니다. 토큰이나 IP를 바꿔 제한을 우회하는 동작은 구현하지 않습니다.

Google Sheets와 Apps Script 기반 인증은 소규모 내부 도구 수준입니다. 데스크톱 프로그램과 외부 `appsettings.json`에 들어간 값은 사용자가 추출하거나 변경할 수 있으므로 결제, 민감한 개인정보 또는 강한 라이선스 보호가 필요한 서비스에는 별도 백엔드와 전문 인증 저장소를 사용해야 합니다.
