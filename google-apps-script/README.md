# Google 스프레드시트 인증 서버 설정

1. Google 스프레드시트를 새로 만들고 URL의 `/d/`와 `/edit` 사이 ID를 복사합니다.
2. `확장 프로그램 > Apps Script`를 열고 `Code.gs`와 `appsscript.json` 내용을 붙여 넣습니다.
3. `configure()`의 `spreadsheetId`, 기본 멤버십 일수, 기본 허용 PC 수, 세션 만료시간을 수정하고 편집기에서 한 번 실행하여 권한을 승인합니다. 기본 멤버십은 1일(종료일자 = 가입일 다음날)입니다.
4. `배포 > 새 배포 > 웹 앱`을 선택합니다.
   - 실행 사용자: 나
   - 액세스 권한: 익명 사용자를 포함한 `모든 사용자`. `나만`, 도메인 사용자, 로그인한 사용자만 허용하는 설정은 데스크톱 앱에서 401/403을 발생시킵니다.
5. 배포된 `/exec` URL을 앱의 `appsettings.json > GoogleAuthentication.WebAppUrl`에 입력하고 `Enabled`를 `true`로 변경합니다.

`테스트 배포`에서 복사한 `/dev` URL은 스크립트 편집 권한이 있는 Google 사용자만 접근할 수 있으므로 앱 설정에 사용할 수 없습니다. 시크릿 브라우저에서 `/exec` URL을 열었을 때 Google 로그인 화면 없이 JSON 상태 메시지가 표시되어야 합니다. 코드를 변경한 뒤에는 `배포 > 배포 관리 > 편집 > 새 버전`으로 다시 배포해야 `/exec`에 반영됩니다.

`configure()`를 실행하면 `회원정보`, `이력`, `공지사항`, `회원_단체` 탭 및 헤더가 자동 생성됩니다. 회원정보의 멤버십 기간, 사용가능PC수, 등급은 관리자가 시트에서 직접 변경할 수 있습니다. 등급 기본값은 `1`이며 광고분석 권한을 부여할 회원은 `2`로 변경합니다. 기존 회원의 등급 빈 셀도 서버 요청 시 `1`로 자동 보정됩니다.

로그인 사용자가 `내 매물 불러오기`를 누르면 매물 조회 전에 `회원_단체` 탭의 `id`, `단체id` 열에서 연결 정보를 확인합니다. 같은 회원과 단체 ID 조합이 없을 때만 새 행을 추가하므로 중복 저장되지 않습니다.

공지사항은 `공지사항` 탭의 A1 `공지내용` 헤더 아래 A2부터 한 행에 하나씩 입력합니다. 빈 행은 제외되며 로그인할 때 최대 100개의 공지가 앱으로 전달됩니다.

기존 회원의 비밀번호 해시는 새 버전 배포 후 첫 정상 로그인 때 현재 형식으로 자동 전환됩니다. 기존 해시 검증이 필요한 첫 로그인만 오래 걸릴 수 있으며 이후 로그인은 단축됩니다.

회원가입 시 `멤버십 시작일자`는 가입일, `멤버십 종료일자`는 항상 가입일 다음날이 `yyyy-MM-dd` 형식으로 저장됩니다(예: 2026-08-20 가입 → 종료일자 2026-08-21, 가입 당일 하루 사용 가능). 스크립트 속성 `DEFAULT_MEMBERSHIP_DAYS` 값은 가입 기본값에 영향을 주지 않습니다. 로그인과 heartbeat는 시각을 제외한 날짜만 비교하며 종료일 당일부터 사용할 수 없습니다. 기간 연장은 관리자가 시트에서 종료일자를 직접 변경합니다.

## 이력 탭 (접속 관리)

접속 상태는 `이력` 탭 하나에서 **토큰당 1행**으로 관리합니다. 토큰은 서버의 비밀값과 앱이 전송한 PC 식별자를 조합해 만들므로 **계정×PC 조합마다 하나**이며 같은 PC에서는 항상 동일합니다. 로그인은 기존 행을 갱신(없으면 새 행 추가)하므로 행이 누적되지 않고, 시간이 지나도 조회 속도가 떨어지지 않습니다.

| 컬럼 | 갱신 시점 | 설명 |
| --- | --- | --- |
| 토큰 | 최초 1회 | 계정×PC 식별자. 이력 탭의 기본 키 |
| 아이디 | 최초 1회 | 동시 접속 PC 수를 세는 기준 |
| PC명 | 로그인 | 앱이 보낸 컴퓨터 이름 |
| 아이피 | 로그인 | 로그인 시점의 공인 IP |
| 앱버전 | 로그인·heartbeat | 지원 문의 대응용 |
| 세션ID | 로그인 | heartbeat 검증용. 같은 PC 재로그인 시 새로 발급되어 이전 세션 무효화 |
| 최초로그인일시 | 최초 1회 | 이 PC를 언제부터 사용했는지 |
| 최종로그인일시 | 로그인 | 마지막 실제 로그인 시각 |
| 최종접속일시 | heartbeat | **만료 판정 기준**. 이 값으로만 세션 유효성을 계산 |
| 종료일시 | 종료 시 | LOGOUT·EXPIRED 등이 발생한 시각 |
| 상태 | 상태 변경 시 | `ACTIVE` / `LOGOUT` / `EXPIRED` / `PC_LIMIT` / `MEMBERSHIP_EXPIRED` / `MEMBER_DELETED` |

`최종로그인일시`와 `최종접속일시`는 서로 다른 값입니다. heartbeat가 1분마다 `최종접속일시`만 갱신하므로 실제 로그인 이력이 덮어써지지 않습니다.

## PC 수 제한과 PC 교체

이 프로그램은 **PC 대당 설치**해서 사용합니다. 사용가능PC수는 **로그인할 때 아이디 기준으로 등록된 행 수**로 판정합니다. 상태값과 무관하게 행이 있으면 그 PC는 자리를 차지한 것으로 봅니다.

- 이미 등록된 PC에서 다시 로그인하는 것은 언제든 허용합니다(기존 행 갱신)
- 새 PC는 등록 대수가 사용가능PC수 미만일 때만 등록합니다
- 한도를 넘으면 `PC_LIMIT`으로 로그인이 차단됩니다

**PC를 교체하면 관리자가 `이력` 탭에서 이전 PC 행을 삭제**해 자리를 비웁니다. `PC명`, `아이피`, `최종로그인일시` 컬럼으로 어느 행이 어떤 PC인지 구분합니다. 행을 지우면 그 PC에서 실행 중이던 앱은 다음 접속 확인 때 세션을 찾지 못해 자동 종료됩니다.

시간 경과로 세션을 끊지 않으므로 절전·통신 두절로 재로그인을 요구받는 일이 없습니다. 세션 만료 시간(`SESSION_TIMEOUT_SECONDS`)과 5분 주기 정리 트리거는 더 이상 사용하지 않습니다.

## 접속 확인 주기 — 하루 1회

`멤버십 종료일자`는 날짜 단위이고 서버도 시각을 뺀 날짜만 비교하므로, 멤버십 상태가 바뀌는 시점은 **자정뿐**입니다. 그래서 앱은 **로그인할 때 한 번, 그리고 날짜가 바뀐 뒤 한 번만** 서버에 확인합니다.

앱은 20분마다 깨어나지만 **날짜가 그대로면 서버에 아무것도 보내지 않습니다.** 날짜가 바뀐 것을 확인했을 때만 요청을 보내므로 상주 실행 중 서버 접속은 **하루 1회**입니다. PC가 절전 상태로 자정을 넘겨도 깨어난 뒤 20분 안에 확인이 이뤄집니다.

멤버십이 종료되면 그 확인에서 `MEMBERSHIP_EXPIRED`를 받아 앱이 종료됩니다. 회원 삭제와 관리자의 PC 행 삭제도 같은 확인에서 감지되므로, 반영까지 최대 하루가 걸립니다.

세션 만료 시간만 바꾸려면 `DEFAULT_SESSION_TIMEOUT_SECONDS` 값을 고친 뒤 `applySessionTimeout()`을 실행합니다. `configure()`와 달리 스프레드시트 ID를 건드리지 않아 운영 중에도 바로 적용됩니다.

이 구조는 소규모 라이선스 관리용입니다. Apps Script 웹 앱을 익명 공개하면 누구나 엔드포인트에 요청할 수 있고, Google Sheets는 전문 인증 데이터베이스가 아닙니다. 결제·개인정보·대규모 서비스에는 별도 서버와 검증된 인증 체계를 사용하세요.
